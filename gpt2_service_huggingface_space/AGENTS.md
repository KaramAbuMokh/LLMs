# gpt2_service_huggingface_space — AGENTS.md
Purpose: the GPT-2 portfolio demos (Game of Thrones question model with retrieval, and the spam detector) as ONE Docker service on the PUBLIC Hugging Face Space
`karamAM/gpt2-demos` (cpu-basic, 2 vCPU, 16 GB). Same `/health` and `/generate` shape as `../gpt2_service`, so the portfolio only needs a URL change; the Game of Thrones
answer gains `retrieval_used` and `sources` (the `completion` key is unchanged). The original `../gpt2_service` and the GitHub repo LLMs are untouched. Weights are NOT here:
they sit in the PRIVATE Hugging Face model repo `karamAM/gpt2-got-and-spam-weights`, and the retrieval index in the PRIVATE dataset repo `karamAM/gpt2-got-retrieval-index`;
both are downloaded at startup with the Space secret `HF_TOKEN`. Design: `../docs/DESIGN.md`.

## API (what the portfolio calls)
- `GET /health` -> `{"ok": true, "models": ["got", "spam"], "weights_repo_commit": "51cb85f8", "memory_mb": 3366, "peak_memory_mb": 3827, "retrieval": {"ready", "index_version", "index_revision", "passages", "pairs", "text_encoder", "reranker_enabled", "prompt_layout", "problem"}}`.
- `POST /generate` with JSON `{"prompt": "...", "task_name": "got" | "spam", "max_new_tokens": 120}` (optional: `temperature` 0.1-2, `top_p`, `top_k`, `repetition_penalty`, `stop`, `use_retrieval`). Game of Thrones -> `{"completion", "retrieval_used", "sources": [{"source_type", "book", "chapter", "snippet"}]}` plus a `Server-Timing` header; spam -> exactly `{"completion"}`. Errors: 422 bad input (including a question over 864 tokens: "Questions can be up to N tokens."), 429 too fast, 503 line full (`Retry-After` set). Sampling fields left out take the server defaults of `service_settings.py` (`RequestDefaults`). A retrieval problem never becomes an error: the answer falls back to the plain prompt and `retrieval_used` is false.
- Environment overrides (all read in `service_settings.py`): `GOT_RETRIEVAL_ENABLED`, `GOT_RETRIEVAL_INDEX_REVISION`, `GOT_RETRIEVAL_RERANKER_ENABLED`, `GOT_PROMPT_LAYOUT`, `GOT_BOOK_SNIPPET_ENABLED`, `GOT_PAIR_EXAMPLES_ENABLED`, `GOT_MAX_REQUESTS_IN_LINE`, `TORCH_THREADS`, `WEIGHTS_REPO_ID`, `GOT_WEIGHTS_FILE_NAME`; secret `HF_TOKEN`.

## Differences from the old service (on purpose)
- Game of Thrones answers: the old code used a prompt unlike the training one, ignored the API's temperature/top-k/top-p, returned the prompt plus an invented next question and always produced 50 tokens. Defaults now (all in `service_settings.py`): temperature 0.3 (chosen on the fact-development questions, confirmed on the 30 facts, 2026-10-25), top-p 0.9, top-k 40, repetition penalty 1.1, 120 tokens. The request shape is unchanged.
- Spam now really classifies; padding is 120 tokens, not 1024. Both models stay loaded together; no API key.
- Generation uses a preallocated key/value cache (no re-reading of the whole text per token), stops at 25 seconds, and the prompt is never silently cut from the left: retrieved text is packed within a token budget and the question block is always kept.
- Privacy and copyright: logs hold ids, scores and timings only (the memory line carries the fixed label `after_got` or `after_spam`, never caller text); no response field shows more than 25 words of the books: the snippet is cut at 25 words, and every completion on every route is checked against a hash of every 26-word run of all passages and cut at the first hit. The check needs the book index: with the retrieval kill switch on, or after a failed start (see `/health` `retrieval.book_runs`), it has nothing to compare with.
